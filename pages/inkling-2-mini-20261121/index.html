Inkling 2 Mini: How Looping Adds More Reasoning to a Small Open Model

By Dekrov Published Nov 21, 2026 Updated Nov 21, 2026

Inkling 2 Mini is an open-weight 26.4B-parameter model that reuses its middle layers for extra computation. Its coding results and offline Mac demo are promising, but the scores are provider-reported and the demonstrated computer had 48GB of memory.

Start with the plain-English explanation ↓

Overview

Thinking Machines Lab released Inkling 2 Mini on November 20, 2026. It combines a sparse mixture-of-experts model with a looped transformer: the middle layers run repeatedly for each token. The lab says the model has 26.4 billion total parameters, 3.4 billion active, and a roughly 20GB weight footprint. It is distributed with open weights under Apache 2.0, making local inference and downstream integration possible. The interesting claim is not simply that a laptop can run it; it is that a compact model can spend more computation on each token without storing repeated copies of those middle layers. [1]

Technical Deep Dive

How it works

The model has 24 decoder layers. The first six run once, the middle twelve (layers 7–18) run three times with shared weights, and the last six run once. That produces 48 layer applications per token from 24 stored layers. Each layer uses a sparse expert system: a token is routed to eight of 128 experts. The loop raises effective active computation to about 5.4B parameters per token, even though 3.4B parameters are active in the ordinary model-count sense. Most weights use NVFP4, with the final four layers in MXFP8. The lab’s explanation is that repeated middle-layer passes can refine internal representations before the model emits text; this is an architectural rationale, not proof that every coding task improves.

Official statement

The release announcement and model card describe the architecture and publish the reported evaluations. They are provider sources: their benchmark results are useful starting points, not independent replications. The same announcement explicitly says evaluation setups vary across models, so a leaderboard row is not a controlled head-to-head test. [1]

What the published scores do—and do not—show

Thinking Machines reports 48.2% on DeepSWE v1.1 using mini-swe-agent v2.4.6, compared with 42.2% for Qwen3.8-27B in its table. It reports 79.2% on SWE-bench Verified with a bash-only setup, compared with 77.8% for Qwen3.8-27B. These are vendor-published results, and the source cautions that evaluation setups vary across models. They should be read as promising claims to reproduce, not as a definitive ranking. [1][2]

The same release lists weaker results on multi-turn constraint following: 50.0% on MultiChallenge and 33.4% on ComplexConstraints v1.1, behind Qwen3.8-27B on both. The model is therefore not a universal small-model winner; the company positions it for long-horizon agentic tasks. [1]

Local does not mean any laptop

The checkpoint is about 20GB, but that is not the total runtime memory requirement. The model card recommends Apple silicon with 32GB or more, or GPUs with at least 32GB VRAM; the flight demo used an M5 Pro MacBook Pro with 48GB in airplane mode. The video is sped up 15×. It demonstrates a real local coding session as described by the authors, while leaving actual latency, sustained load and performance on lower-memory machines unanswered. [1][3]

For local serving, the repository documents Transformers, SGLang and vLLM, plus llama.cpp for quantized GGUF versions; it also lists Apple-silicon options such as Ollama and Exo. The published license is Apache 2.0. Hosted inference and customization are available through Tinker, but the announcement does not state a price. [2][3]

Explained Simply

A transformer is a neural network that repeatedly processes tokens, the pieces of text it reads and writes. Inkling 2 Mini has 24 learned layers, but it sends each token through the middle twelve layers three times. The model reuses those same weights instead of copying the middle layers, spending more computation while keeping the stored model smaller.

Think of a writer who rereads the middle of a draft twice before finishing it. The writer can reconsider the same material without hiring two extra writers or keeping three separate copies of the desk. The analogy is imperfect, but it captures the trade: more processing per token, with shared parameters. That may help a coding agent work through a sequence of tool calls while keeping the model’s files on a local machine.

The weights are downloadable, and the project documents local support through Hugging Face Transformers, SGLang, vLLM, and other runtimes; llama.cpp support is for quantized GGUF versions. The model page recommends at least 32GB of memory for Apple silicon or VRAM. The showcased airplane-mode flight-simulator run used a MacBook Pro M5 Pro with 48GB, so it does not establish that the model will run comfortably on every 20GB laptop. Offline inference also means no network-based retrieval: the model can use only its prompt, local tools and local files. Teams should test their own hardware, runtime, context length and agent harness.

Conclusion

Inkling 2 Mini is a credible new option for developers who want open weights, local inference and agentic coding capability in a compact memory footprint. Its looped middle layers are the technical story; its coding benchmark lead and flight demo are claims from the maker, not independent confirmation. Before adopting it, check that your machine has practical memory headroom, choose a supported runtime, and benchmark it on your own repository and agent harness. The public materials do not yet establish how it performs across independent real-world coding workflows.
