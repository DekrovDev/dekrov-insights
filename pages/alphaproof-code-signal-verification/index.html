AlphaProof Code and Signal: What the Machine-Code Proof Actually Establishes

By Dekrov Published Nov 10, 2026 Updated Nov 10, 2026

Google DeepMind used AI agents and Lean to check cryptographic properties of a compiled Signal protocol implementation. The result is significant, but it is not a universal security certificate for the Signal app.

Start with the plain-English explanation ↓

Overview

On November 10, 2026, Google DeepMind announced AlphaProof Code, a multi-agent framework that generated machine-checked Lean proofs for compiled code from the Signal protocol's Rust implementation. Its headline achievement is a connection between selected cryptographic guarantees and actual AArch64 machine instructions, not merely a high-level design model. [1] [2]

The researchers report about 6.5 million lines of Lean proof, backed by roughly 26,000 lines of trusted specifications and machine semantics. Those figures describe formal proof artifacts, not application source code or a security score. [2]

Technical Deep Dive

Target and build

The team linked unmodified libsignal into a command-line harness and compiled it to AArch64 using a pinned Rust toolchain. The published repository identifies libsignal v0.105.4 and spqr v1.6.0. This is not a verification of every Signal release or mobile application build. [2] [3]

Agent-assisted proof

Researchers and AI specification-writing agents translated security goals into formal statements. Humans approved those statements. Autonomous agents then constructed proofs, while a gatekeeper accepted results only after the Lean kernel checked them and a comparator matched the statements against held-out specifications. [2]

This limits the risk of an agent fabricating a convincing-looking proof, but not the risk of choosing an incomplete specification. [2]

What is proved

The paper covers the PQXDH handshake and Triple Ratchet, reporting confidentiality, authentication, forward secrecy and post-compromise security in defined symbolic and computational threat models. Quantum-related handshake secrecy is described specifically in the symbolic model; it is not an unconditional claim about every future quantum attacker. [2]

Trusted assumptions

The trusted base includes approximately 18,000 lines of specifications and 8,000 lines of AArch64 semantics and mapping, Lean's kernel, cryptographic primitive contracts, external routine contracts and assumptions about the execution environment. The result is conditional on those foundations and the exact compiled binary. [2] [3]

Bug mutation test

The researchers restored two historical, previously fixed bugs in isolated code and used Lean to establish that the resulting binaries violated the symbolic security theorems. This tests whether the selected properties reject known faults; it does not guarantee detection of every unknown vulnerability. [1] [2]

Reproduction and costs

The public repository provides a paper-to-code map, pinned dependencies, proof sources and replay instructions. Its README estimates several hours and roughly 15–34 GiB peak RAM for the default build. Dekrov has not replayed these proofs independently. DeepMind reports four weeks of work, while WIRED notes that the company declined to disclose costs or commit to a commercial product. [3] [4]

Official statement

The published artifacts document conditional guarantees for a specified machine-code target, not independent certification of every deployed Signal application. [2] [1]

Explained Simply

Imagine a messenger's encryption as a secure delivery service. Engineers can test thousands of deliveries, but testing alone cannot examine every possible sequence of lost keys, malicious messages and unexpected actions. Formal verification instead asks whether a mathematically defined rule could ever be broken under stated assumptions. [2]

There is another gap: a delivery plan is not the same as the truck on the road. Software written in Rust is converted into machine instructions before it runs. DeepMind's researchers connected the mathematical security rules to a particular compiled version of Signal's protocol code. AI agents helped produce the very long proof, and a smaller trusted mathematical checker examined it. [1] [2]

To check that the rules were meaningful, researchers reintroduced two previously fixed bugs and demonstrated violations of the rules. That is a stronger, narrower result than an AI simply saying that code looks secure. [2]

But this does not mean “Signal can never be hacked.” The work does not cover every device, app screen, group-chat feature, malicious operating system or future implementation. It relies on approved specifications and assumptions about cryptography. A proof cannot catch a problem it was never asked to consider. [2] [4]

Ordinary users do not need to install anything new because of this announcement; keeping apps and devices updated remains sensible. For developers, the lesson is to combine precise requirements and machine-checked proofs with testing, audits and transparent documentation of what remains outside the model. [3] [4]

The verified properties strengthen confidence in a narrow encryption component without removing device-security risks.

The paper makes its assumptions public; ordinary users should continue installing security updates.

Conclusion

The researchers have published substantial, machine-checked proof artifacts linking selected Signal security guarantees to a compiled binary. The open questions concern the trusted specification, broader app coverage, independent reproduction and practical cost at scale. [2] [3] [4]
