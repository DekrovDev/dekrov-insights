Codex CLI 0.169.0 Turns the Terminal into a Multi-Chat Agent Workspace

By Dekrov Published Nov 15, 2026 Updated Nov 15, 2026

OpenAI’s November 13 release is less about a new model and more about the agent workspace around it. Codex CLI 0.169.0 adds multiple persistent side-chat tabs, task-history search, terminal-managed custom providers, collapsible turn detail, local diagnostic exports and a stricter trust rule for non-interactive runs. The release is substantial for daily workflow, but it publishes no speed, quality or reliability benchmark.

Start with the plain-English explanation ↓

Overview

Codex CLI 0.169.0 was published as a stable release on November 13, 2026. Its headline change is an opt-in terminal workspace where several side conversations can remain open as tabs, be selected with keyboard or mouse, and be reopened after restarting Codex. The same release adds search across older tasks by name, prompt preview or working directory. [1]

This changes the shape of terminal work. A developer can keep the main implementation thread focused while opening separate conversations for investigation, review or documentation, then recover those branches later. It does not mean the model became more capable, and OpenAI supplied no comparative task benchmark for the release.

Official release evidence

The release note and linked implementation pull requests establish what shipped. They do not measure whether multiple chats improve completion rate, code quality or token efficiency. [1]

Technical Deep Dive

Side chats become a persistent workspace

The implementation arrived in several layers: sidebar support for multiple side chats, persistence and close controls for local workspace chats, then keyboard and mouse navigation between tabs. OpenAI’s release note says saved local side chats can be reopened after restart, so these are no longer merely disposable tangents inside one live terminal session. [2] [3] [4]

An earlier community feature request described the practical problem: one side chat was insufficient when several tangents needed isolated context, while separate terminal instances lost their relationship to the parent work. That request was closed as “not planned” in May, but the core multi-chat idea later shipped in 0.169.0. This is historical community context, not evidence about production reliability. [8]

Task search and quieter transcripts

The agent command center can now search older tasks using a task name, prompt preview or working directory. A separate Collapse turn details setting groups completed activity beneath each prompt while preserving visible answers and searchable tool output. These changes target retrieval and readability rather than inference quality. [1]

Custom providers move into the terminal UI

Version 0.169.0 can add or edit a custom model provider from the terminal. When custom-gateway onboarding is enabled, a provider can be created during sign-in; supported gateways can use device-code authentication for SSH or browserless environments. The app-server documentation exposes provider listing and configuration methods, including provider IDs, base URLs and provider-specific settings. [5] [6]

This is an integration feature, not a promise that every OpenAI-compatible endpoint will behave identically. Model availability, authentication, tool support, context limits, billing and data handling still belong to the selected provider. A custom gateway also changes the trust boundary: prompts and code may travel through infrastructure other than OpenAI’s default endpoint.

The non-interactive trust boundary tightens

The most important safety fix is easy to miss. In untrusted directories, codex exec now keeps project configuration and project MCP servers disabled even when --sandbox workspace-write is used. The operator must explicitly use --trust with codex exec or codex review to save trust for that project. [7]

The distinction matters because filesystem write permission and configuration trust are different decisions. A writable sandbox should not silently authorize repository-supplied instructions or MCP endpoints. The new behavior makes that separation explicit for non-interactive automation.

Operational fixes around long sessions

The release can save a diagnostic ZIP locally with Ctrl+S even when uploads are disabled. It also fixes terminal sessions waiting indefinitely for MCP servers missing from a shared app-server report, prevents delayed aborts from interrupting a later turn, repairs quoted cmd.exe handling and an unreadable-parent PowerShell case on Windows, and updates bundled SQLite to 3.54 for write-ahead-log fixes. [1]

Plugin marketplace upgrades can reuse Git objects already present on disk, reducing repeated downloads. These changes improve failure recovery and local workflow friction, but the release note provides no quantitative latency, memory or stability measurements.

Practical Upgrade Guide

Install or update the CLI, then verify the actual version rather than assuming a global package updated itself:

npm install -g @openai/codex@0.169.0
codex --version

After upgrading, test the opt-in terminal workspace with a disposable repository before moving an important active session. For a custom provider, verify the endpoint owner, authentication method, model catalog, retention policy and billing before sending private source code. In CI or scripted work, treat --trust as a deliberate security grant rather than a convenience flag.

Explained Simply

A desk with several labeled notebooks

Think of the old terminal session as one notebook on a desk. If you paused coding to investigate an error, compare two approaches and draft documentation, all three detours could crowd the same notebook. Side chats are separate notebooks connected to the same job. Version 0.169.0 lets several of them stay open as tabs and restores saved local ones after a restart.

The task search is the filing cabinet: it can find older work by its name, part of the prompt or the folder where it ran. Collapsed turn details hide the long trail of tool calls until you need it, while keeping the final answer and searchable output available.

Choosing a different engine

A custom provider is like connecting the workspace to a different engine. Codex can now help configure that connection inside the terminal, including browserless device-code sign-in for supported gateways. The interface is easier, but the operator still has to check who runs that engine, what models and tools it supports, where data goes and what it costs.

Writing files is not the same as trusting a project

The security fix separates two permissions. Allowing a sandbox to write in a folder does not automatically mean Codex should trust configuration or MCP servers supplied by that folder. In untrusted directories those project settings remain off until the operator explicitly grants trust. That is safer for downloaded or unfamiliar repositories, but the protection can still be overridden intentionally.

The practical result is a better-organized terminal agent, not a smarter model. Upgrade if persistent parallel investigations, searchable task history, custom gateways or the trust fix matter to your workflow. Do not cite 0.169.0 as evidence of higher coding accuracy: no such benchmark was published.

Conclusion

Codex CLI 0.169.0 is a meaningful workspace release. Persistent multi-chat navigation reduces context mixing, task search improves recovery of old work, provider configuration becomes more accessible, and non-interactive execution gets a clearer trust boundary. The strongest evidence is the stable release note, implementation PRs and app-server contract. What remains unknown is equally important: OpenAI published no independent usability study, coding benchmark or reliability delta for these changes. Evaluate the workflow features directly, keep custom-provider data boundaries explicit, and grant project trust only when the repository has been reviewed.
