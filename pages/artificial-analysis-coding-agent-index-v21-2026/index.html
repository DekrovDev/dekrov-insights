The New Coding-Agent Index Tests Models Inside Their Tools

By Dekrov Published Nov 14, 2026 Updated Nov 14, 2026

Artificial Analysis’s November 2026 Coding Agent Index v2.1 scores a model together with its agent harness and settings. Its published rows show why one leaderboard score can hide different capabilities, costs and runtimes.

Start with the plain-English explanation ↓

Overview

Artificial Analysis now labels its public coding-agent leaderboard v2.1. It combines three kinds of work—changing real repositories, completing terminal tasks and answering questions about code—and gives each benchmark equal weight. That makes the result a useful workflow snapshot, but it is not a pure model ranking: each row represents an agent harness, model and settings together.[1]

Technical Deep Dive

How it works

The version history says v2.1, current in November 2026, upgraded Terminal-Bench 4.0 to 4.1 and replaced 100-task FrontierCode v1.1 with FrontierCode-AA 2.0, a 132-task implementation of Cognition’s FrontierCode 2.0. It also aligned cost estimates with Artificial Analysis’s model-evaluation method. Because two benchmark components and the pricing calculation changed, a v2.1 result should not be compared casually with an older index version.[2]

Official statement

Artificial Analysis says each benchmark component is averaged over three attempts per task and the three component scores receive equal weight. The score therefore summarizes a chosen suite; it is not the percentage of all 322 tasks passed, nor proof that one model will win on a developer’s own repository.[2] [1]

How v2.1 Builds Its Score

Three different workloads

FrontierCode-AA 2.0 asks an agent to change real open-source repositories and grades the patch against blocking and non-blocking checks, including whether a maintainer would merge it. The 132 tasks are not publicly released. Artificial Analysis runs each task three times, caps an attempt at 500 turns and checks trajectories for attempts to look up the upstream solution.[2][4]

Terminal-Bench 4.1 covers 66 terminal tasks across areas such as software engineering, machine learning, scientific computing, security and system administration. Version 4.1 keeps the 4.0 tasks and environments, but updates verifiers to reduce reward hacking and correct cases where valid answers were rejected. SWE-Atlas-QnA-AA tests whether an agent can trace code and answer repository questions; its 124 tasks use a rubric-based pass/fail score.[2]

A composite, not 322 equally pooled tasks

Each component score is averaged over three attempts per task, then the three component scores are averaged equally. This gives each benchmark one-third of the headline index even though the components contain 132, 66 and 124 tasks. It is therefore not equivalent to pooling 322 tasks and counting one overall pass rate. Artificial Analysis publishes the component scores so readers can see when an aggregate hides a capability gap.[1][2]

Cost and time are estimates with scope limits

The cost column is a pay-per-token API estimate using token counts and provider pricing, with cache discounts and cache-write charges where applicable. Artificial Analysis says it may use recorded run cost when it cannot rebuild token counts. This is not subscription-plan pricing, infrastructure cost or the total cost of a human-reviewed production workflow. The reported agent wall time also excludes environment startup, verifier and judge time.[1][2]

Independent evaluation

These are Artificial Analysis’s published measurements for specific agent/model/settings combinations. We found no independent reproduction of this exact comparison in the sources reviewed. FrontierCode-AA 2.0’s task set is private, which limits outside replication; that is a constraint to account for, not evidence that the scores are wrong.[2][4]

Explained Simply

A coding model is the system that reasons and writes code. An agent harness is the software around it: it gives the model files to inspect, tools to run, and a loop for checking results. Artificial Analysis measures these combinations, so “Claude Code with Fable 5.2” and “DeepSeek Harness with DeepSeek V4.1 Flash” are full setups, not just model names.[1]

Think of a model as an engine and the harness as the car around it. A strong engine can be slowed by poor controls, while a well-designed car can make a less powerful engine useful. The index tries three driving conditions: modify a real codebase, complete a terminal task, and explain how a repository works.

For a real project, compare the benchmark’s per-category results, then test candidates on a small set of your own issues with the same repository, tools, tests and time limit. A single aggregate number hides whether you need implementation, terminal operation or codebase understanding. The public FrontierCode tasks are withheld, and the published comparison is Artificial Analysis’s evaluation rather than an independent reproduction, so treat it as useful evidence—not a guarantee.

Conclusion

The most useful signal is the trade-off, not a single winner. Claude Code’s Fable 5.2 High and Opus 5.5 Max rows both score 58, but their component strengths differ; Fable High costs less in this run. DeepSeek Harness is far cheaper on the published API-cost estimate, while scoring lower on repository changes and terminal tasks. These are evaluator results for particular configurations, not a promise about subscription plans or your own codebase. Compare the task mix and test your workflow before switching.
