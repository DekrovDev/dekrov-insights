VS Code 1.146 Adds Agent Inbox and Multi-Model Comparison

By Dekrov Published Nov 14, 2026 Updated Nov 14, 2026

VS Code 1.146 adds an experimental agent Inbox, expands model comparison to include Copilot Fusion, and begins a three-month countdown to removing the Local harness. Here is what the new comparison flow can—and cannot—tell you.

Start with the plain-English explanation ↓

Overview

Released on November 11, VS Code 1.146 brings agent-session triage and model comparison closer to everyday coding work. The comparison flow can run one prompt against two to ten available models, optionally use a judge, and synthesize a new result; the same release also marks the Local harness for removal in February 2027. [1][2] [1]

Technical Deep Dive

How it works

VS Code 1.146 became Stable on November 11, 2026. In the Agents window, start a repository session, choose Compare Models, and add two to ten available models. For code work, attempts can use isolated worktrees; for chat-only questions, the judge and synthesizer can now run without a workspace. Fusion and its supported effort tiers can act as an attempt, judge or synthesizer. The separate agent-driven evaluation tools can discover models, launch comparisons and read their results, but they are Experimental, require `sessions.chat.compareAgents.tools.enabled`, and are off by default. [1][2]

Official statement

Microsoft documents the product behavior and labels the main comparison flow Preview; it labels agent-driven evaluations Experimental. The release provides no independent accuracy, coding-benchmark or productivity result, so availability should not be read as proof that one model wins. [1]

What model comparison actually does

In a repository session, the Agents window can run attempts in separate worktrees, letting you inspect each proposed code change without the attempts editing the same working tree. A judge can evaluate the results; a synthesizer can use the judge verdict and identified strengths to create a new session or implementation. Synthesis is an explicit action and does not merge changes into your branch. [2]

The comparison documentation allows two to ten models. Available choices depend on the configured harnesses, credentials and enterprise policy. The automatic Auto choice is not available in comparisons, though a supported model can be added more than once at different thinking-effort levels. [2]

What the 1.146 changes mean in practice
ChangeStatusPractical boundary
Compare ModelsPreviewTwo to ten available models; model access and setup vary. Compare in the Agents window, not editor Chat. [2]
Agent-run evaluationsExperimentalOff by default; requires Compare Models and a setting. Manual comparisons remain available if the tools are disabled. [1]
Inbox modeExperimentalOff by default; groups sessions that need attention, are working, ready to merge, on hold or done. Snoozing does not archive a session. [1]
Local harnessDeprecatedFunctionally frozen and scheduled for removal in February 2027; the Copilot harness is already the default for new sessions. [1]

A model comparison is not always a model-only comparison

VS Code distinguishes the model from its harness. The harness prepares context, coordinates tools and approvals, and maintains the agent conversation; using the same model with a different harness can change how the task is carried out. That means cross-harness comparisons answer “which configured agent setup worked better here?” unless the other conditions are controlled. This is an inference from Microsoft's description of the harness boundary, not a benchmark result. [3]

The Local harness deadline is a separate migration story

New sessions have defaulted to the Copilot harness since VS Code 1.143. In 1.146, the Local harness is deprecated, receives no guaranteed new features, and is planned for removal in February 2027. Microsoft says the Copilot harness uses the Copilot SDK and Agent Host, and supports managed sandbox and permission policies that the Local harness cannot enforce. Existing customizations and integrations may differ, so the transition guide recommends reviewing and verifying the workflow before switching. [1][3]

Evidence, coverage and what remains untested

The official release notes and documentation establish the controls, prerequisites and feature status. A Microsoft VS Code issue records the Fusion comparison request, its implementation and closure for milestone 1.146; that is a useful engineering trace, not evidence of user satisfaction. [4]

Independent coverage from Visual Studio Magazine summarized the Inbox, chat windows and comparison changes, but did not publish a head-to-head model evaluation. No independent benchmark or sufficiently detailed user-run comparison was found for this release at review time. Consequently, there are no supported claims here about which model is fastest, cheapest or most accurate in this workflow. [5]

Evidence limit

A judge score is one model's evaluation of other outputs, not a standardized external benchmark. For code, inspect the diffs and run the same acceptance tests before choosing a result. The official documentation also says each attempt, judge and synthesis is separate model work, but publishes no per-comparison price. [2]

Explained Simply

A coding agent is a model plus the software around it: the editor gives it files, tools, approvals and a place to run commands. VS Code 1.146 lets you send one task to several available models or agent setups and inspect their answers or code side by side. The feature lives in the Agents window, not the regular editor Chat view.

Think of the comparison flow as a small bake-off inside the editor: several cooks receive the same recipe and ingredients, then a reviewer checks the dishes. In a coding task, the “ingredients” are the repository, prompt, tools and permissions. If those differ between attempts, the result tells you about the whole setup, not just which model is smarter.

You can compare available models or harnesses in the Agents window and review separate attempts. The interface does not make the comparison a controlled benchmark: access, credentials, harnesses and enterprise policies affect which options appear, and each attempt, judge and synthesis is separate model work. It does not automatically merge the selected result. [2]

Conclusion

The release makes multi-model work easier to organize and adds Fusion to the comparison path, but the feature remains Preview and the agent-driven evaluation tools are Experimental and off by default. No independent benchmark or published model score is included in the release notes. Try it on a small, repeatable repository task: hold the prompt and acceptance checks steady, inspect every diff, run the project tests, and treat the judge as a reviewer rather than ground truth. Teams still using the Local harness should inventory customizations and permissions before migrating ahead of February 2027.
