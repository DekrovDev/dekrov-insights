Browser Use 1.0.6 Changes the Default Model and Its Cost

By Dekrov Published November 16, 2026 Updated November 16, 2026

An omitted model setting now selects BU 4.0 on the Browser Use gateway. Here is what changes for existing automation budgets.

Start with the plain-English explanation ↓

Overview

Browser Use 1.0.6, released November 16, changes the hosted model selected when an application leaves its model unspecified. Both the default Agent constructor and the default gateway wrapper now select BU 4.0. An unchanged application can therefore see a different bill after upgrading. [1]

Technical Deep Dive

How it works

The release notes list BU 4.0 at $1.80 input and $9 output per million tokens, up from $0.12 and $0.60 for BU Fast. Both rates are 15 times higher. The default reasoning setting also moves from medium to high. Actual task cost depends on token consumption, retries and the number of steps. [2]

Official statement

The maintainers report a short test that cost $0.022 with the new default and $0.0014 with the previous one. This single example does not establish a typical bill or a success-rate improvement. The older setup documentation still identifies BU Fast as the default and its evaluated configuration. [1]

Compare the options before upgrading

Keep the existing gateway model explicit if predictable pricing matters. The maintainers also list BU 4.0 Mini and Pro as options for simpler and harder tasks respectively. The general model guide describes external providers as another route, which changes credentials, billing and potentially the way reasoning is configured. This article does not infer the Mini or Pro prices from the default model’s rate. [2]

For a useful comparison, run repeatable checks against an owned staging application. Hold the browser, task inputs, version and retry policy fixed. Record medians for cost and time alongside success counts, with failures included. Older benchmarks tied to BU Fast do not measure the new default.

Explained Simply

The browser library controls the browser. A model decides what action to take next. When the application leaves the model choice blank, the library picks one. This update changes that choice on the Browser Use gateway.

Imagine a team runs the same staging-site check every morning. After updating the dependency, the job can use a pricier model even if nobody changed the check itself. The bill depends on what the model actually had to read and write.

The release notes say explicitly selecting BU Fast preserves the prior model choice. Compare the models on the same staging site, with the same task set and stop conditions. Count completed checks, overall cost and run time before switching a recurring job.

Conclusion

Review both the library version and the configured model. A same-provider trial is the easiest way to isolate this change. Compare cost per successful run rather than token prices alone, and track the jobs that fail or hit a deadline.
