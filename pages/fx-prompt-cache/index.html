Vercel fx 0.0.17 Makes More of the Prompt Cache

By Dekrov Published November 16, 2026 Updated November 16, 2026

Vercel reports smaller tool definitions and higher cache reuse in its coding agent. What the numbers mean for long sessions.

Start with the plain-English explanation ↓

Overview

Vercel’s fx 0.0.17 release on November 14 brings subagents and prompt-cache changes. The most useful optimization is how it sends context across turns. The maintainers report that cache reads accounted for 82.0% of later input in their live tests across nine model families, up from 61.3%. [1]

Technical Deep Dive

How it works

A prompt cache lets a provider reuse work on repeated input. Editing older context can break a reusable prefix. The release describes preserving prior turns, delivering attached-file rules as notes and dropping older images in groups. It also reports that built-in tool definitions shrank by 48.0% and the first request in a new session by 32.4%, compared with 0.0.16.

Official statement

These are maintainer measurements. The cache percentage is a share of later input, not the share of tasks completed or the discount on the total bill. A provider can price cache reads and writes differently. Output tokens, cache expiry and tool execution also matter. [1]

Subagents also land in this release. For a fair upgrade test, first compare a single-agent run and keep worker count fixed. In a second test, enable delegation and record aggregate usage across workers. An improvement on one parent request may be offset by work done elsewhere in the session. [1]

Explained Simply

A coding agent often sends the model instructions, tool descriptions and the conversation so far before asking for its next decision. The model provider may reuse work when parts of that input match an earlier request.

Think of an editor and a colleague who already read the same project brief. Sending a short addendum can be cheaper than asking the colleague to reread a rearranged brief. The closer the earlier part stays to its original form, the more work the provider can potentially reuse.

The change is most relevant for long sessions with recurring tool calls. For a short task, smaller tool definitions may matter more than cache hits. To see whether the upgrade helps your work, compare the cost and time for the same tasks with the same model and provider.

Conclusion

Vercel reports changes to both prompt size and reuse across turns. To compare the old release, the new one and another agent, start with the same repository and model. Record cache-read, cache-write, uncached input and output separately. Then compare elapsed time and cost per passing task. The release figures do not provide an independent cross-agent comparison.
