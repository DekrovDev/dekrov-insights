Telegram Widget RCE Claim: What the Android Demo Shows—and What Remains Unverified

By DekrovPublished November 11, 2026Updated November 11, 2026

A newly released Telegram feature lets bots embed interactive HTML widgets directly in chat bubbles. Security researcher V12 reportedly demonstrated Android Calculator opening after a widget interaction. Telegram subsequently confirmed the Android issue was fixed November 10 and deployed to all users November 11. Here is the architecture, reported behavior and remaining technical unknowns.

Start with the plain-English explanation ↓

Overview: release, report and evidence

On November 9, Telegram's Bot API 10.4 introduced sendWidget and related widget support. In production, bots can currently send these widgets in private chats, and forwarding is disabled; wider group and inline features remain on the test server. [1] [2]

On November 11, Kod.ru reported a demonstration attributed to security researcher V12. The Android sequence reportedly shows a bot chat, a Start interaction, a widget with a countdown, and the system Calculator opening. The researchers labeled it a Telegram Widgets RCE demonstration. The initial report lacked exploit details, affected versions, platform scope and independent reproduction; Telegram later confirmed a fix. [3]

Reported exploit; fix confirmed by Telegram

A video of Calculator opening is a meaningful claim, not public proof of a complete arbitrary-code-execution chain. The original public report lacked an exploit chain and affected-version matrix. Later on November 11, Telegram's verified @telegram account stated that the Android issue had been fixed on November 10 and that the fix had been deployed to all users earlier on November 11. The statement does not provide a client version, patch commit or technical root cause. [3]

Timeline

  1. November 9 — Bot API 10.4 adds HTML widget methods. [2]
  2. November 10 — Coverage explains the QuickJS-based, in-message feature and limited rollout. [4]
  3. November 11 — V12 Android RCE claim and Calculator demonstration reported; mechanism not disclosed.
  4. November 11 — Telegram's verified @telegram account says the Android issue was fixed the previous day and the fix deployed to all users earlier on November 11. [3]

Technical deep dive: what actually runs

1. A widget is code inside a message, not a Mini App

Telegram widgets contain a self-contained HTML document with inline CSS and JavaScript: up to 32,768 bytes of HTML and 4,096 bytes after compression. Unlike Mini Apps, widgets are not hosted websites opened in a WebView. The Telegram client executes their scripts in a QuickJS sandbox and renders allowed interface elements using the app's own UI. [1]

Examples include a live poll, a countdown, a game board or a price display. The code is immutable after the bot sends it; state can change through Telegram-managed updates. The client enforces a restricted HTML/CSS/JavaScript profile and resource limits. [1]

2. The intended security boundary

The documented sandbox blocks direct network APIs such as fetch, XMLHttpRequest and WebSockets. External scripts and remote images cannot load. The widget can request limited information from its own bot through TelegramWidget.request(), carried by Telegram rather than a raw socket. The bot, not the widget, changes shared or chat state. [1]

This architecture matters because running JavaScript in a widget is expected behavior. A security failure would require escaping its restricted capabilities or abusing a privileged interface outside the intended widget model. The public report does not establish which boundary, if any, was crossed. [1] [3]

3. What the Android demonstration would imply

In the reported sequence, the Android Calculator opens after the widget countdown. If the behavior was caused by widget-supplied instructions escaping isolation, it would be evidence of unintended interaction with Android capabilities. It does not by itself establish unrestricted shell commands, data theft, persistence, zero-click triggering or a universal exploit on every platform. [3]

A demonstration app such as Calculator is often used because its launch is visible and relatively harmless. It is not proof that an attacker could automatically install an application or compromise every Telegram user. The underlying exploit primitives, prerequisites and reliability have not been published in the reviewed sources.

4. Who could be exposed?

Production widgets are currently limited to private conversations with bots; they are not generally available as arbitrary forwardable group or channel messages. Earlier Telegram Info beta coverage had already raised concerns about executing widget scripts inside messages, but did not independently establish this exploit. [5] The demo involved Android, and the available reporting does not verify exploitability on iOS, desktop or web. Do not extrapolate from a single Android video to all Telegram clients. [1] [3]

5. Telegram confirms the Android fix

Update, November 11: Telegram's verified @telegram account posted: “This issue in Telegram for Android was fixed yesterday, and the fix was deployed to all users earlier today.” In context, this dates the fix to November 10 and deployment to November 11. This is a first-party confirmation of remediation for the Android issue, not an independently verified technical root-cause analysis. Telegram did not specify a version number, commit, exploit chain, or whether the remediation was client-side or server-side in that statement. The official widget documentation still describes the API and its rollout. We have not independently tested the fix. [1] [2] [3]

Practical scenarios and precautions

A normal, safe widget

A legitimate bot could send a countdown timer: its JavaScript updates the visible numbers inside the chat bubble. The timer should have no access to other apps, local files or unrestricted network requests. This is precisely the kind of interactive behavior the feature is designed for. [1]

What would make the reported behavior abnormal?

Imagine the same timer causing Android to open an unrelated system application without the user explicitly requesting it. That would be outside the timer's ordinary display responsibilities and would warrant investigation. This analogy explains the reported symptom; it is not a working exploit or a reproduction.

What users and bot developers can do

Keep Telegram updated through trusted channels. Until the claim is clarified, avoid experimenting with unfamiliar bots that send new interactive widgets. Do not treat a countdown or attractive interface as proof that a bot is safe. Bot developers should use documented widget APIs, validate all bot-side requests and avoid treating widget-provided data as trusted. [1]

These are cautious risk-reduction measures, not proof that a specific version is vulnerable or that avoiding widgets is a complete defense. We have not conducted an exploit test.

Explained simply

Why is there JavaScript inside a chat?

Telegram now lets a bot send a tiny interactive panel instead of a plain text message. You might see a poll with moving bars, a timer or a mini game right in the conversation. The panel uses HTML and JavaScript, just like some web pages, but Telegram is supposed to keep it locked in a small, controlled box.

What is the scary part?

Think of a toy car in a fenced playground. It is allowed to drive around inside the fence. If it suddenly opens your real garage door, something has gone wrong with the boundary. In the reported video, a Telegram widget is followed by Android's Calculator opening. The claim is that the widget crossed a boundary it should not cross. We do not yet know how, or whether independent testers can repeat it.

Does this mean someone can hack my phone?

Not on the evidence currently public. The report concerns one Android demonstration, not a documented mass attack. Telegram's verified account says the Android issue was fixed November 10 and deployed to all users November 11. That is official confirmation of a fix, although no exact version or root cause was provided. Keep Telegram updated and be selective about unfamiliar bots; there is no published proof here of a zero-click attack.

Conclusion

The widget launch is real, and its design introduces a powerful new execution surface inside messages. The V12 Android RCE claim deserves serious scrutiny. Telegram has now confirmed the Android issue was fixed and the fix deployed to all users, but has not explained the exploit chain, root cause or specific patch. The next decisive technical evidence would be a researcher write-up, independent reproduction or a verifiable client/server change. Until then, separate documented architecture from reported exploit behavior. [1] [2] [3]
