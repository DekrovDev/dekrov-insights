MiniMax M3.1 Flash in OpenCode

By DekrovPublished Nov 10, 2026Updated Nov 10, 2026

OpenCode now lists MiniMax M3.1 Flash as a limited-time free model. It combines a 1M-token context, a 428-billion-parameter mixture-of-experts design and ambitious coding benchmarks. But independent agent tests reveal a more complicated story: fast output is not necessarily fast task completion.

Start with the plain-English explanation ↓

Overview

As of November 10, 2026, OpenCode Console publicly lists MiniMax M3.1 Flash Free with model ID minimax-m3.1-flash-free, and prices input, output and cached-read tokens as free. OpenCode explicitly describes this as a limited-time offer; no precise expiration date is published in that listing. [1]

It also states that the serving provider follows a zero-retention policy and does not use requests for model training. These are provider statements, not an independent privacy audit. [1]

The model itself is not newly launched today: MiniMax introduced M3.1 Flash on October 19, 2026. Its official card reports roughly 428B total and 23B active parameters per token, with up to 1 million tokens of context. The key news here is a useful temporary OpenCode access route, not a November 10 release of the base model. [2] [3]

We reviewed primary documentation, an external coding benchmark and contemporary developer discussions. Dekrov did not run an independent M3.1 Flash benchmark; the comparisons below are attributed to their evaluators, with dates and limits.

Technical Deep Dive

How the model stays efficient

MiniMax uses mixture of experts (MoE): a routing system activates a subset of specialized neural modules for each token instead of using every parameter simultaneously. [3] [4]

The official card identifies MiniMax Sparse Attention, quantization-aware training and a DSpark speculative decoding head. Together these are intended to reduce per-token computation and improve serving throughput, while the entire model's stored weights still demand substantial memory. [3] [4]

The company describes a native multimodal model accepting text, images and video and producing text. This is understanding, not native image/video generation. [3] [4]

The model card describes up to 1M input context; a separate registry lists 512K maximum output. Those are published capability ceilings, not a promise that OpenCode's free endpoint accepts 512K generated tokens, never throttles or can maintain perfect reasoning over every long project. Reasoning is always on in the official model family, with adjustable effort in supported integrations. [3] [4] [8]

Release versus provider availability

  1. Sep 27 — a preview variant appears in model catalogs, before the final model launch. [8]
  2. Oct 19 — MiniMax launches M3.1 Flash and presents vendor speed/capability figures. [2]
  3. Oct 22 — some r/opencode users report that an earlier free promotion has ended. This is a time-bound user report. [6]
  4. Nov 10 — the current official OpenCode Console page lists MiniMax M3.1 Flash Free again. The exact reopening time and future expiration are not established here. [1]

There are three separate access routes. OpenCode Console's free promotional listing is one; MiniMax's paid API is another; self-hosting the published model weights is a third. Their account permissions, latency, data handling, hardware requirements and model identifiers can differ. [1] [2] [3]

Token speed is not job speed

The MiniMax launch post claims 170+ tokens per second at median (P50) and occasional speeds above 200 tokens/s on its serving setup. It says online inference is almost three times faster and total agent-task cost about 70% lower than the previous generation. [2]

These are company-reported comparisons: they do not measure OpenCode Free response times, and a low unit price does not establish a low cost for a long sequence of repeated tool calls. [2]

Agents do more than generate one answer. They read files, run shell commands, evaluate failures, plan patches, ask for more tokens, reread context and sometimes retry the same broken approach.

In a long run, the number of iterations and tool round trips may be more important than peak output speed. A large context can be useful, but it is not proof that an old assumption survives compaction or that a model will stop itself from looping.

What MiniMax’s benchmarks show

MiniMax reports 73.7% DeepSWE v1.1 for software engineering, 76.2 BankerToolBench for multi-step real-world workflows, 61.7 OSWorld V2 for computer operation and about 82% CyberGym for security-related evaluation. [2]

Its published model card also presents 38.1 on Terminal Bench 4.0 versus 42.3 for DeepSeek V4.1 Flash-1017 in the same table. These are vendor-reported scores, not Dekrov-run tests. They cannot be combined into one universal ranking across model versions or harnesses. [2] [3]

Vendor evidence

Benchmark results describe particular task suites, versions, tooling and evaluation conditions. A reported 82% CyberGym score does not certify an AI agent as a safe autonomous security auditor. [2]

What independent tests found

Bito published an outside comparison updated October 24, 2026. It reported 8 long coding-agent sessions and 16 short questions, holding prompts and its scoring approach constant within that experiment. MiniMax M3.1 Flash scored 73% on long sessions; DeepSeek V4.1 Flash-1017 scored 77% and Claude Opus 5.5 scored 87%. For short questions MiniMax scored 86%, versus DeepSeek's 90%. [5]

More strikingly, Bito measured 42.8 minutes for an average MiniMax long session versus 15.4 minutes for DeepSeek 1017. It describes MiniMax making about 368 model requests and emitting around 290,000 output tokens for a long session. [5]

One reasonable interpretation is that extra reasoning/tool loops erased a faster per-token benefit. This is Bito's setup (its own services, task mix and AI judging), not an independent OpenCode Free latency test, and its sample is limited. [5]

Community: both interest and friction

A October 20 r/opencode discussion praises the model's generous context while other participants prefer DeepSeek V4.1 Flash or GLM for coding. An October 22 thread reports an earlier promotional free variant disappearing. These dated anecdotes use unspecified endpoints, workloads and configurations; they are neither controlled experiments nor evidence that today's model listing has disappeared. [6] [7]

How to test it responsibly in OpenCode

From OpenCode, use /models and select MiniMax M3.1 Flash Free; if needed, follow Console's /connect flow for the connected provider. The listed catalog ID is minimax-m3.1-flash-free. Check your own account's access. [1]

The official OpenCode documentation describes the model's serving provider as zero-retention and not using user data for model training, but sensitive credentials should never be pasted into an unreviewed tool context regardless of provider assurances. [1]

A useful controlled test is to give M3.1 Flash and a familiar competitor the same repository state, failing test, acceptance criteria and stop rule. Record wall time, passed checks, lines changed, number of tool calls, loops, and whether a human review catches regressions.

The next task should begin with a clean context if the agent starts solving outdated requirements. This is a proposed method, not an experiment claimed by Dekrov.

Explained Simply

How it works

Think of MiniMax as a huge workshop full of specialists. The entire workshop is enormous, but only a few specialists work on each part of a question. That's how it can have hundreds of billions of parameters without doing the full amount of computation for every word it generates. The model can work with code and documents, and it can examine pictures or video, while its answer is text.

What the free offer includes

The model is advertised as being able to read a very big notebook — up to one million tokens of context. That might be useful when an AI assistant has to look at many files. But it does not mean the free OpenCode server promises unlimited requests or that every piece of a very long conversation will stay important to the model.

Right now, OpenCode publicly lists an option that costs nothing for ordinary input and output tokens. The company explicitly calls this a temporary offer. It's different from paying MiniMax for API requests. If you already use OpenCode, it is an interesting model to add to your choices, not something you have to buy just to try. [1] [2]

Why fast answers can mean slow tasks

Speed is the tricky part. Imagine a typist who can type 200 words in a minute but keeps rewriting the same paragraph. The typing is fast; finishing the letter is slow. MiniMax advertises fast token output, while one external study found that its long coding tasks took much longer than a DeepSeek comparison. Neither fact contradicts the other — they measure different things. [2] [5]

What to try next

The practical advice is simple: pick a small real programming bug with a test that tells you whether it is fixed. Let MiniMax try, then try your usual model. Keep whichever solves the problem more reliably, with fewer unnecessary steps. Big context, free pricing and impressive benchmark charts are useful clues, but passing tests and making sensible changes matter more.

Conclusion

MiniMax M3.1 Flash has a compelling combination of large-context MoE design, published open weights and currently free OpenCode access. But the strongest supported conclusion is it deserves a controlled trial, not that it is the new best coding agent. [1] [2] [3] [5]

Official throughput figures and Bito's slower long-run outcomes describe different measurements; the free offer's duration and operational quota are not guaranteed. [1] [2] [3] [5]

Start with bounded code-reading or debugging tasks. Compare against another model using actual tests, and keep a human review for security-critical changes. The exact free endpoint may change after this November 10 snapshot.
