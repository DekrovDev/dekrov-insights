ClawDOS: A Claude Coding Agent on a 1980s IBM PC XT

By Dekrov Published Nov 22, 2026 Updated Nov 22, 2026

ClawDOS squeezes a modern coding-agent loop into DOS: the 176 KB harness runs on an 8088-based IBM PC XT, while a separate machine handles TLS to Anthropic’s API. The project is a striking constraint demo, not evidence that a 1980s PC can run an AI model locally.

Start with the plain-English explanation ↓

Overview

Published by Ricapar in November 2026, ClawDOS is a DOS chat and coding harness that calls Claude through Anthropic’s Messages API. The author documents a 176 KB DOS executable, 18 tools for files, programs, screenshots, memory and hardware ports, and a bridge computer for HTTPS. It is notable because it moves the agent runtime onto hardware with an 8088 at 4.77 MHz and 640 KB RAM, while leaving model inference in the cloud. [1]

Technical Deep Dive

How it works

The DOS program stores prompts, tools, and chat history on disk; streams Messages API replies; parses tool calls; and runs the requested DOS tools. A separate tunnel machine handles TLS and can hold the API key, so the XT uses ordinary TCP/IP through an mTCP packet driver. The repository documents 31 boot tests against a mock API in DOSBox-X, unit tests on DOS, and runs in 86Box; its README also shows a demo filmed on original hardware. Those are project-reported test and demonstration details, not an independent audit. [1] [2]

Official statement

The public source and API guide establish the architecture the author implemented and the request shapes the harness sends. They do not establish production reliability, security against malicious prompts, or general compatibility with every Messages-API provider. “Runs on an IBM PC XT” refers to the client harness; inference and TLS are offloaded. [1]

The README reports 13,000 lines of C/C++, an 8086-targeted build, a 176 KB harness, 31 DOSBox-X boot tests against a mock API, DOS unit tests and 86Box runs. Its demo includes a live-API coding task and a separate video from original hardware. These numbers and demonstrations come from the author’s repository; this review did not reproduce them. [1] [2]

Tools, persistence and the approval boundary

The published tool list includes file reads and writes, search, directory operations, command execution, screenshots, memory and I/O port access, plus speaker output. The agent can compile and run programs with DOS toolchains. The project says safe mode is on by default and asks before file, memory or port changes; F3 turns it off. That design makes consequential actions visible, but it is not a formal security sandbox. [1]

Conversation history and memories are stored as files on the XT. The API guide explains how a conversation can continue with a thread identifier and only newly added messages, while replaying the full history when continuation is uncertain. The repository also describes prompt caching to reduce repeated uploads on a slow link. [2]

What this does not prove

  • It does not run Claude locally; model inference uses Anthropic’s hosted API.
  • The original-hardware demo is distinct from the emulator-based screenshots and test runs; not every displayed result is from physical hardware.
  • The README’s tests are project-maintainer tests. No independent reproduction of performance, security or reliability was found.
  • The TLS bridge adds a separate machine and networking setup; it is not a self-contained offline agent.
  • The repository is GPL-3.0-or-later, but its README cautions against redistributing a built disk image that includes Turbo C; follow the exact license notes for bundled components. [1]

Explained Simply

A coding agent is a loop: send instructions to a model, receive a tool request, run that tool, return its result, then continue. ClawDOS implements that loop as a DOS program. The language model itself is not inside the old PC; the XT sends requests to a modern hosted API through a network bridge.

Imagine an old terminal operator calling a powerful remote expert. The XT can read and write its own files, start its compiler, and send a screenshot, but the expert’s reasoning happens in a distant data center. That separation is the trick: a constrained machine can host the controls and tool loop without hosting the AI model.

The design shows that an agent runtime can be small and that local tools can be exposed through explicit interfaces. The trade-offs are substantial: a bridge machine remains necessary, API calls need connectivity and paid access, screenshots and round trips take time, and the agent can request file, program or port actions. Safe mode asks before changes by default, but that is a user approval boundary—not a proof that all actions are harmless. Treat it as an educational project and inspect permissions before adapting the design.

Conclusion

ClawDOS is best read as a systems-engineering experiment: old hardware hosts a modern agent harness, while the network bridge supplies TLS and cloud inference. Its README gives useful implementation detail, tests, and demonstrations, but most performance and reliability claims are project-reported. For modern coding work, the useful lesson is architectural: keep the model remote, make tools narrow and visible, persist conversations explicitly, and preserve human approval for consequential actions.
