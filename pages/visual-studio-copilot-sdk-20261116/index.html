Same Model, Better Agent: Visual Studio’s Copilot Upgrade

By Dekrov Published Nov 16, 2026 Updated Nov 16, 2026

A coding agent is more than its language model. Microsoft’s November 10 announcement reports more successful C# tasks with the same GPT-5.6 Sol model after a change to Copilot’s execution layer. The new experience is default in Visual Studio 2026 version 18.12. The evidence is promising, but vendor-reported.

Start with the plain-English explanation ↓

Overview

Visual Studio 18.12 moved Copilot Chat to the Microsoft Copilot SDK developed by GitHub. The shared technology also underpins GitHub’s CLI and desktop app and VS Code. The change affects how the assistant carries out work, rather than requiring developers to select a new model. [1]

Technical Deep Dive

How it works

An agent harness connects a language model to its working context, tools and feedback. In agent mode, Copilot can edit files, execute commands, inspect test output and attempt corrections. In 18.11 the refreshed chat was optional; 18.12 enables it by default. [2] [3] [4]

Official statement

Microsoft’s comparison holds the named model constant. It does not establish statistical significance across repeated runs or isolate a particular prompt, tool or scheduling change. [1]

What the benchmark measures

Microsoft’s .NET team selected real C# issues spanning legacy and modern .NET, cloud workloads and desktop applications. Success required the previously failing tests to pass while existing passing tests stayed green. Both reported runs used GPT-5.6 Sol. [1]

That is 21 additional successful tasks, a 13.4 percentage-point improvement, or approximately 20.4% more resolved tasks relative to the previous result. The headline counts refer to this C# set, not a cross-language aggregate. [1]

What developers can now control

New capabilities include steering an active request, inspecting operation output, following delegated agents and setting a working folder outside the open solution. Built-in review agents offer additional perspectives; their suggestions still need human review. The release notes describe shared infrastructure for Ask and Agent modes. [1] [2] [3]

Shared foundation is not feature parity

Microsoft says skills can be reused between its four Copilot surfaces. This does not imply identical tool permissions, IDE features or approval policies. Visual Studio retains its own debugging and build integrations. [1] [2]

Migration caveats and rollback

Plan mode and conversation exports were still being migrated at announcement time. Developers relying on them can switch off the refreshed chat under Tools → Options → GitHub → Copilot → Copilot Chat, then restart Visual Studio. [1] [3]

Community Reactions

Individual commenters describe custom prompt files no longer appearing and previously approved benign commands needing manual confirmation. These are migration reports, not verified universal regressions. If you rely on either workflow, compare the old and new chat before switching your team. [5]

External reporting emphasizes the potential reduction in manual cleanup, but repeats Microsoft’s own evaluation rather than presenting a replication. No independent reproduction of the headline benchmark was identified for this article. [6]

Explained Simply

Imagine two mechanics with the same knowledge but different workshops. One can access better tools, see test results and ask another mechanic to check a plan. They might fix more problems without becoming more intelligent. A coding model is the mechanic; the agent harness is the workshop. [1]

In Microsoft’s test the old workshop completed 103 jobs and the new one 124, from the same collection of 157. For a developer this could mean fewer incomplete fixes, not necessarily faster or cheaper work. The test does not show what will happen on your own repository. [1]

If you use Visual Studio 18.12, try the new chat on a small real bug and run your tests yourself. You can redirect the assistant while it works and inspect its actions. Some familiar features are not yet migrated; the old experience remains an option. [1] [2]

Conclusion

The agent environment is an engineering variable worth measuring alongside the model. Start with a representative backlog, hold model and task constant, record test success, time, requests and cost, and inspect regressions. Treat Microsoft’s reported gain as a reason to evaluate the upgrade, not a promise that every workload will improve. [1] [3]
