Claude Code 2.1.323 Batches Tool Calls—and Moves the Permission Boundary

By Dekrov Published November 16, 2026 Updated November 16, 2026

Claude Code 2.1.323 adds an experimental Code Mode in which Claude writes JavaScript that can coordinate several tool calls in one step. The release also makes plugin compatibility explicit and fixes multiple cases where permissions, sandboxing or identity boundaries could fail in surprising ways. The trade-off is important: faster orchestration concentrates more behavior into code that Auto Mode evaluates as a unit.

Start with the plain-English explanation ↓

Overview

Anthropic released Claude Code 2.1.323 on November 12, 2026. Its headline feature is Code Mode, an opt-in experiment where Claude writes JavaScript to search, filter, edit and run tools instead of issuing every tool call separately. The same release adds Claude Code version ranges for plugins, TypeScript hook checks, long-hook heartbeats and a large set of permission and sandbox fixes. [1]

This is a tool-execution and control-plane change, not a new Claude model. The practical question is not only whether several operations can be grouped, but where approval, visibility and policy enforcement now occur. Anthropic’s documentation says Auto Mode reviews the generated code rather than every individual tool call, while the conversation shows the resulting tool actions and keeps the JavaScript in the transcript viewer. [2]

Evidence boundary

The feature mechanics and shipped fixes below come from Anthropic’s release notes and documentation. Two regression sections describe open GitHub issues with reproduction details; they are user reports, not proof that every installation or platform is affected. [3] [4]

Technical Deep Dive

One JavaScript program can coordinate several tools

In a normal Claude Code turn, the model requests a tool, reads its result and decides what to call next. In Code Mode, the model can write a JavaScript fragment that runs independent calls in parallel, feeds one result into another operation and returns only the subset of output needed for the next reasoning step. Anthropic’s example searches for a retry policy, edits the selected file and runs a targeted test from one generated program. [2]

The user still sees the tool calls and diffs. The generated JavaScript is hidden from the main conversation but can be inspected in the transcript viewer with Ctrl+O. Code Mode therefore reduces the model-facing round trips between related operations; it does not make the underlying tool effects invisible. [2]

Auto Mode reviews the program, not every call

The most consequential limitation is explicit in the documentation: Auto Mode’s classifier reviews the JavaScript program rather than each individual tool call. That can preserve a useful approval boundary if the program is understandable and its effects are bounded, but it also means a loop, dynamically selected path or dependent command may represent more authority than a single visible tool request. [2]

Code Mode does not bypass hooks. Anthropic says PreToolUse hooks can refuse tool calls, and UserPromptSubmit hooks can block code output. The release also fixes several broader enforcement gaps: some permission checks missed parts of Bash commands or evaluated rm from the wrong folder; certain wildcard allow rules, wrappers and shell options could skip prompts; sandbox exclusions could let an unnamed command run outside the sandbox; and a failed sandbox setting in claude -p or the Agent SDK now stops startup instead of running Bash unsandboxed. [1]

The experiment is intentionally narrow

Code Mode requires Claude Code 2.1.323 or later, the native build and an interactive terminal session. It is unavailable through -p, the Agent SDK, VS Code, Desktop and cloud sessions. It also does not support Remote Control, Claude in Chrome, computer use, background-session transfer or background forks. Generated code normally stops after ten minutes unless its work can run in the background. [2]

Eligible accounts are Claude subscriptions or Console accounts using supported direct access. The documentation excludes gateways, Amazon Bedrock, Claude Platform on AWS, Google Cloud’s Agent Platform, Microsoft Foundry, HIPAA configurations and zero-data-retention organizations. Supported models are Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.2. A repository cannot silently enable the feature because project settings are not allowed to activate its environment variable. [2]

Plugin Compatibility Becomes Enforceable

Plugins can declare a Claude Code version range

Version 2.1.323 adds engines["claude-code"] to plugin.json. A plugin outside its declared compatible range is not installed, updated or loaded; installation and update choose the newest plugin version that satisfies the range. This turns compatibility from a README promise into an enforceable installation decision. [1]

The validator now type-checks TypeScript hook modules. Findings are warnings by default, while claude plugin validate --strict fails on them. It also reports the $ nouns that a mod’s engine.create hook adds, withholds or replaces. Together, those checks make extension behavior easier to inspect before deployment, although they do not establish that a plugin is safe or semantically correct. [1]

Long hooks and embedded sessions get clearer lifecycle signals

The release adds a heartbeat every 30 seconds while hooks run for a long time in claude -p and SDK sessions. The purpose is to keep an embedding host from treating a live turn as hung. It also adds warnings when a plugin language server cannot start and names what operators should inspect. [1]

Early Regression Signals

One Windows report measures a slower first request

An open issue reports that the first API request from each 2.1.323 process took roughly 5.5–7.5 seconds to receive its first byte, compared with about 0.6–1.5 seconds on 2.1.322 in the reporter’s Windows 10 environment. Later requests in the same process returned to roughly 0.5 seconds. The issue includes alternating-version measurements and debug timing, but the reporter had not reproduced it on another machine or network. [3]

This is relevant to short-lived claude -p wrappers and routers with tight timeouts, but it should not be generalized into a confirmed cross-platform regression without additional reproduction or an Anthropic fix statement.

Another report says per-subagent status customization disappeared

A separate open issue says 2.1.323 removed the effect of subagentStatusLine, leaving custom per-agent context, cost, model, effort and cache indicators unavailable. The reporter compares behavior with 2.1.322 and points to the schema marking the setting deprecated. The issue asks Anthropic to restore the hook or ship an equivalent mod render site. [4]

The release notes list the removal elsewhere in the full change set, so the configuration change is real; the claim that no adequate replacement exists and the operational severity are community assessments. Teams that depend on custom subagent telemetry should test their status display before rolling out the update broadly.

Practical Adoption Checklist

  1. Start in a disposable branch. Code Mode is experimental and may change or disappear in a later release.
  2. Inspect the generated program. Use the transcript viewer when a task contains loops, dynamic paths or bulk edits.
  3. Keep hooks and hard policy controls. A classifier reviewing a program is not a substitute for sandboxing, deny rules and protected paths.
  4. Test the exact surface. Code Mode is terminal-only and cannot be assumed to work in SDK, IDE, Desktop or cloud workflows.
  5. Pin plugin compatibility. Add a deliberate Claude Code engine range and run plugin validation in strict mode before release.
  6. Measure startup and observability. If automation launches short-lived processes or relies on subagentStatusLine, compare 2.1.322 and 2.1.323 in your own environment.

Explained Simply

From one instruction at a time to a small script

Normally, Claude asks to use one tool, reads the answer and then asks for the next tool. Code Mode lets it write a short JavaScript program that can search several places, choose a file, edit it and run tests as one coordinated operation.

The speed-up changes what must be reviewed

Think of the difference as approving individual errands versus approving an itinerary. The itinerary can be faster and avoid unnecessary back-and-forth, but it may include a loop or a decision that covers more files than expected. Auto Mode reviews that program as a unit, while hooks and the sandbox still need to control the actual operations.

It is not the default or a universal Claude feature

Code Mode is off by default, experimental and available only in a limited terminal setup with specific accounts and models. It does not currently work through the SDK, non-interactive -p, VS Code, Desktop or cloud sessions. Test it on a reversible task before trusting it with a large repository.

Conclusion

Claude Code 2.1.323 is more than a convenience release. Code Mode can reduce orchestration overhead by letting the agent batch related tool calls, while plugin engine ranges and strict hook validation make extensions easier to govern. The same release hardens multiple permission, sandbox and identity edges that matter even when Code Mode is disabled.

The feature remains a narrow experiment. Its program-level Auto Mode review, limited surfaces and account restrictions require deliberate testing. The two early regression reports add useful warning signals for short-lived automation and subagent observability, but they remain open community reports rather than independent evidence of universal failure.
